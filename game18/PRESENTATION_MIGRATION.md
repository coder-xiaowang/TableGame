# game18《犯人在跳舞》演出事件迁移

## 本阶段目标

- 由服务端为出牌、指认、目击、神犬、少年、交易、情报交换、谣言和结算生成有序演出事件。
- 用行动者到目标玩家或公开牌迹的轨迹，恢复线下桌游的行动方向感。
- 将公开事件和私人事件分开裁剪，动画只消费服务端已经授权给当前视图的数据。
- 保持既有权威规则、旁观系统、移动端左右两列座位和 SQLite 房间恢复兼容。

## 信息边界

- 所有人可见：谁出牌、公开牌名、谁对谁发起目击、搜查、交易或指认、谁已完成秘密选择、公开结算。
- 仅目击者可见：目标玩家的具体手牌牌名。
- 仅少年和当前犯人分别可见：少年确认的犯人身份、犯人已被认出的通知。
- 仅牌的交出者与接收者可见：交易、情报交换和谣言中实际移动的牌名。
- 旁观者和无关玩家永远只接收公开事件，不从动画字段获得额外牌值或犯人身份。

## 验收标准

1. 相同公开事件在玩家和旁观者视图中一致，私人事件只进入授权玩家视图。
2. 目击公开展示行动方向，但具体手牌只在目击者界面出现。
3. 少年事件的公开部分不含犯人 ID；发动者和犯人各自收到正确的私人提示。
4. 交易、情报交换、谣言在公开层只展示一张秘密牌发生移动，具体牌名仅双方可见。
5. 新事件按全局序号播放，重连不回放旧积压，连续事件不乱序。
6. 手机端仍使用既有左右两列玩家布局，轨迹根据真实 DOM 位置计算，不依赖圆桌坐标。
7. 缺少演出字段的旧 SQLite 快照可恢复；序列化、持久化、权威服务和 UI 契约测试通过。
