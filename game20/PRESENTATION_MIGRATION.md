# game20《局内人》演出层迁移说明

## 目标

在不改变权威规则、隐藏身份和秘密投票边界的前提下，让线上问答呈现出“发言—回应—审查—揭晓”的桌游节奏。演出事件由服务器在真实状态转换点写入；客户端只负责播放，不能借动画决定规则结果。

## 服务器事件

| 事件 | 场景 | 公开范围 |
| --- | --- | --- |
| `round-start` | 新一轮和公开主持人 | 全员、旁观者 |
| `secret-progress` | 一份秘密信息已确认 | 只公开数量，不公开确认者 |
| `questioning-start` | 猜词计时开始 | 全员、旁观者 |
| `master-answer` | 主持人的“是/不是/不知道” | 全员、旁观者 |
| `correct-guess` | 主持人确认猜中者 | 全员、旁观者 |
| `discussion-ready` | 玩家准备投票 | 全员、旁观者 |
| `vote-sealed` | 玩家已提交密票 | 只公开提交者和票种，不含选择 |
| `first-vote-result` | 第一次投票揭晓 | 结算后公开统计 |
| `second-vote-start` | 进入局内人指认 | 全员、旁观者 |
| `tie-break-start` | 平票候选人与裁决者 | 平票形成后公开 |
| `round-result` | 阵营、答案、局内人和最终指控 | 本轮结束后公开 |

同一次用户动作或超时结算使用同一个 `sceneId`。客户端从同一场景中选择优先级最高的事件演出，避免“已投票—统计—结束”逐条积压播放。

## 隐私边界

- 秘密确认事件不得带 `actorId`：否则公开第二位确认者等同于公开局内人。
- `vote-sealed` 不得带 `accuse`、候选目标或票值。
- 当前答案和局内人身份只能在 `round-result` 中出现；此时权威状态已经进入 `roundEnd`。
- 旁观视图与普通公开视图收到同一套公开演出事件，不生成“旁观者特供”的额外秘密。

## 客户端节奏

- 首次加入与断线重连只建立游标，不重播历史事件。
- 正常演出约 1.35 秒；队列达到 2 个场景后加速，达到 5 个场景后强压缩。
- 优先级 4 以上的新场景会淘汰尚未播放的低价值提示，但保留重要结算。
- 玩家与中央问答钟盘之间使用虚线轨迹和实体印章；手机端仍使用列表布局，轨迹按实际 DOM 位置计算。
- `prefers-reduced-motion` 下缩短运动时间，但不删除文字结果。

## 验收重点

1. 主持人连续回答时，新回答不会在旧动画之后长时间延迟。
2. 两次秘密投票期间，任何玩家与旁观者都只能知道谁已提交，不能看到投票内容。
3. 局内人先确认秘密时，其他人不能从动画判断确认者身份。
4. 最后一票与投票结算属于同一场景，只重点播放结算。
5. 中途加入、刷新和断线重连不补播整轮旧事件。
6. 桌面和手机端的演出层不阻挡玩家选择与按钮操作。
