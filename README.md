# TableGame

实用工具入口位于 `tools/index.html`：`tools/bead-pattern/` 是拼豆图纸工坊，`tools/puzzle/` 是拼图工坊（原 `game24/puzzle.html`）。两者均为独立静态工具，部署时保留目录结构，通过 `/tools/` 访问；拼图不属于多人桌游，也不需要房间服务器。

原生 HTML/CSS/JavaScript 桌游集合。各游戏通过独立 Node 服务提供页面和房间；共享客户端、服务器与界面能力位于 `shared/`。Just One（`game12`）是未完成的遗留项目，暂不纳入本轮改造。

使用 Node.js 24 或更新版本。在项目根目录启动，例如：

```powershell
node game19/signal-server.js
```

端口与数据库路径参见对应游戏的 `signal-server.js`；用 `PORT` 和各游戏的 `GAMEN_DB_PATH` 配置运行环境，运行数据应放在静态发布目录之外。

## 新桌游上架大厅

玩家从主站 `/index.html` 按人数和玩法选桌。仓库根目录的 `index.html` 提供页面结构，选桌目录、样式和封面位于 `homepage/lobby/`，对外路径为 `/lobby/`。

1. **登记游戏。** 在 `homepage/lobby/app.js` 的 `games` 中填写唯一的 `id`、已开通的子域名前缀 `host`、展示名 `name`、支持人数 `players`、玩法分类 `type` 和一句话介绍 `description`。例如 UNO 的 `host` 为 `uno`，卡片会打开 `https://uno.zillionx.xyz`。介绍写玩家在桌上要做的选择，例如「跟颜色或数字，抢先打空手牌」。可公开试玩的版本可加 `preview: true` 显示「试玩」标记。
2. **核对开局人数和分类。** 按网页版服务端实际允许的人数升序填写。连续人数用 `range(2,6)`，只支持偶数人数就写 `[2,4,6,8]`。优先复用相符的玩法分类，筛选按钮由 `type` 自动生成。「2」至「10」逐一匹配确切人数，「10+」匹配至少支持一种超过 10 人的人数。
3. **准备能认出游戏的封面。** 图片卡将素材放到 `homepage/lobby/covers/<id>.jpg`。牌块或骰子更能代表游戏时，可参考拉密或 Can't Stop，在 `pieces[id]` 配置物件，并在 `homepage/lobby/styles.css` 中补足该游戏的物件样式。用手机双列和桌面宽卡各看一次，确认裁切后仍看得清主要物件。
4. **验收选桌。** 运行 `node homepage/scripts/serve.mjs`，从预览站的 `/index.html` 进入大厅。确认默认列表中只有一张新卡，人数标签与规则一致。分别选择可开局人数、不可开局人数，再叠加玩法筛选，检查卡片显隐、结果数量和清除筛选后的恢复。
5. **验收发布。** 游戏 HTTPS 子域名可以正常建房、加入后再公开卡片。部署时保留大厅入口与 `homepage/lobby/` 的路径映射，随目录一起发布新增的脚本改动、样式和封面。打开公网大厅，确认 `/lobby/app.js`、`/lobby/styles.css` 及使用的图片返回正确内容，再从新卡进入房间。开发中项目可保留独立说明，实用工具走 `/tools/`。

## 验证命令

开发者可通过私有运营报表查看每日访问以及各游戏的开桌、开局、完局和再玩情况。生产采集需要显式启用，配置步骤见[运营统计部署](ops/运营统计.md)。新游戏上架时，同步登记 `shared/server/analytics-games.cjs` 的目录、游戏 ID 和域名，并验证整局结算及同桌再开。

```powershell
npm test
npm run verify
npm run test:shared
npm run test:layout
npm run test:layout:remaining
npm run test:interaction
```

`test:layout` 使用本机 Chrome、临时浏览器配置和内存房间，检查满员对局的座位裁切、重叠、横向溢出，以及独立操作区和座位点击可达性。截图与测量结果写入 `audit/layout-after/`，原审查结果不会被覆盖。默认检查九款游戏；可用 `LAYOUT_GAMES=game18,game19` 缩小范围，使用 `CHROME_PATH` 指定 Chrome 可执行文件。Windows 隔离测试运行器使用 `--no-sandbox`，仅访问自己启动的本地服务；其他平台默认保留浏览器沙箱。

首批布局改造覆盖 `game13`、`game18`、`game19`、`game21`。BANG 和犯人在跳舞通过 `shared/styles/table-layout.css` 共用可用宽高、座位栏和独立操作区；窄屏/短屏使用紧凑座位，内容较多时在桌面内部滚动。美术主题仍由各游戏管理。

后续调整以实机试玩认可的[阿瓦隆布局](game22/VISUAL_DESIGN.md#响应式构图)为参照。先确定玩家做决定时需要同时看见哪些内容，再按可用宽高安排位置。阿瓦隆需要边看远征历史边组队，横屏适合左右分栏；拉密需要在牌架与公共牌组之间移牌，横向空间应优先留给牌桌。空间紧张时，先收起装饰和次要说明，保留能辨认局势的主题元素、可读的文字和容易点到的操作。

每款游戏分别在竖屏和横屏完成一次代表性操作，检查决定所需的信息是否可读、操作是否可达。例如，拉密检查组牌与提交，UNO 检查长手牌中的出牌与选色。是否额外验证进行中转屏、查记录后返回，取决于该游戏是否有相应的使用需求。阿瓦隆保留已通过试玩的选队转屏场景。

其余多人项目已按玩法调整布局。`shared/styles/play-layout.css` 提供通过 `data-play-*` 属性启用的视口外壳：公共桌面独立滚动，操作区在文档流中占位，资料区可展开。各游戏的 `table-layout.css` 保留围桌座次、市场、农场、牌组和地图的不同排布；No Thanks 与截码战采用局部调整。修改布局时应保持玩家 ID、座次规则和服务器的私密视图边界。

`test:layout:remaining` 检查剩余 18 个多人项目的桌面、平板、手机和横屏尺寸；对使用新外壳的项目额外检查展开资料、旁观模式和滚动后的按钮命中情况。结果写入 `audit/play-layout-checks/`。默认速速破译使用 8 人词库局；设置 `GAME1_PLAYERS=32` 时使用玩家出词模式检查 32 人场景，避免内置词库容量限制。PowerShell 可用 `$env:LAYOUT_GAMES='game,game16'` 选择项目。此脚本检查布局与访问性，不替代每款游戏完整流程的联机验收。

速速破译在大厅显示去重后的词库容量，人数不足、离线或词库容量不足时禁用开局；房主可以在大厅切换词库或玩家出词模式。前端与服务端使用同一校验，服务端在任何开局状态变更前执行校验。

`shared/client/mobile-viewport.js` 在新布局项目及截码战中处理文字输入时的可视窗口变化。键盘缩小可用高度时，桌面外壳跟随可视高度，保留操作区滚动；键盘关闭后恢复布局，不禁用页面缩放。新布局包含屏幕安全区边距和触屏输入字号。拉密支持先点选牌、再点目标、新建牌组、取消选牌或放回牌架，桌面鼠标拖放仍保留。

`test:interaction` 使用内存房间、确定性牌面、真实服务器操作和 SSE，以及 Chrome 触摸事件检查：速速破译 32 人开局配置；四款文字输入游戏的草稿与模拟键盘；UNO 长手牌、选色取消与质疑；拉密触屏组牌、撤销、退回和提交；政变证明角色与阻挡；阿瓦隆从组队到任务、刺杀和结算。每个桌面阶段同时检查手机竖屏与短横屏。结果保存在 `audit/play-interactions/`，可用 `$env:INTERACTION_GAMES='game5,game15'` 筛选。操作系统键盘由可视窗口缩小模拟，仍需在真实 Android/iOS 上复核键盘、刘海安全区和触摸手感；这不是所有游戏分支的完整覆盖。

布局样式维护时，由 `shared/styles/play-layout.css` 负责视口高度、滚动和操作区占位，各游戏 `table-layout.css` 负责桌面座位与牌组排布，原主题样式负责颜色、材质和卡牌外观。本轮已清理德州扑克、拉密、政变、局内人中被新布局替代的固定高度、吸底和定位声明；后续新增布局规则应放入对应布局文件。

拉密使用串行编辑同步：开始编辑或重置失败时保留草稿并提供“重试同步”，等待中的请求不会重复发送，旧回合响应不影响新回合。提交牌桌期间防止重复确认。拉密与阿瓦隆在当前标签页的 `sessionStorage` 中保存待提交草稿；刷新后重新加入原房间可恢复。恢复必须匹配房间、玩家、回合或提案，拉密还核对原始牌桌、手牌和牌块守恒；回合结束、超时、转为旁观或更换提案后清除旧草稿。浏览器禁止存储时仍可正常操作，但无法恢复刷新前的草稿。

德州扑克的下注标记和摊牌牌型在座位内部占位，结算结果位于玩家席之后，随公共桌面滚动。多个边池、多人平分及最佳五张牌在窄屏中逐项展开，不再悬浮覆盖玩家席。相关布局位于 `game4/layout.css`。

`npm test` 自动发现所有已开发游戏、共享客户端与服务器、首页的 Node 测试，排除 Just One；摘要与诊断写入 `audit/test-suite/`，失败时返回非零退出码。`npm run verify` 依次执行完整 Node 测试、两组布局检查与交互回归，任何一组失败即停止。完整验收前应清除 `LAYOUT_GAMES`、`INTERACTION_GAMES` 等筛选变量。新增交互场景包括编辑请求失败重试、SSE 断开重连、草稿刷新恢复、重复确认、超时罚牌与旧草稿清除，以及六人全押产生五个平分底池；阶段检查同时断言座位重叠、中心覆盖和视口边界。

真实手机验收尚需 Android/iOS 设备，浏览器模拟不能替代。设备上应复核：中文输入法候选栏展开与键盘打开时旋转屏幕；拉密编辑中切后台、恢复连接和刷新重进；德州扑克多边池结算在刘海安全区、页面缩放和手指滚动下的可读性。当前自动检查只报告 Chrome 浏览器中的结果。
