# game5《UNO》桌面演出层迁移

## 迁移目标

1. 让普通出牌、罚牌、跳过和方向反转不再只是数字与日志刷新，而有明确的牌桌运动和作用方向。
2. 让 `+4` 质疑形成“出牌前摇—质疑指向—公开结算—私人摸牌”的连续事件链。
3. 让喊 UNO、漏喊后的抢抓以及最终胜负成为所有人都能及时感知的桌面事件。
4. 动画只解释服务端已经接受的结果，不参与出牌合法性、抢喊原子性、回合推进或倒计时。

## 信息边界

- 公开事件可以包含：公开打出的牌、选定颜色、行动者、受影响玩家、累计罚牌数量、质疑结算结果、UNO 状态与胜负。
- 私人事件可以包含：自己的起手牌和自己刚摸到的具体牌。
- 公共事件不得包含：牌库顺序、他人手牌、未结算的 `+4` 合法性、待定胜者等权威秘密状态。
- 旁观者只接收公共事件；每位玩家的私人事件独立保存并只合并进本人的裁剪视图。

## 验收标准

- [x] 事件由服务端统一分配全局递增序号并随 SQLite 房间状态持久化。
- [x] 普通出牌指向弃牌堆，`+2/+4`、跳过、质疑与抓 UNO 指向实际受影响玩家。
- [x] 方向反转、喊 UNO、漏喊窗口、牌堆重洗和胜负都有独立可辨认的事件。
- [x] 起手牌和摸牌结果只进入获得者视图，其他玩家和旁观者无法从事件字段恢复牌值。
- [x] `+4` 在质疑结算前不通过演出事件泄露是否合法。
- [x] 首次同步与重连只建立最新游标，不重播整局历史。
- [x] 演出不阻塞操作按钮，不修改服务端截止时间，并支持 `prefers-reduced-motion`。
- [x] 旧版 SQLite 快照缺少演出字段时可以兼容恢复。
- [x] game5 专项测试 34 项以及全仓测试 485 项全部通过。
- [ ] 完成真实联机验收：普通出牌、叠加罚牌、成功/失败质疑、跳过、反转、喊/抓 UNO、超时与终局。
