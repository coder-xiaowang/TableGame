# game21《间谍危机》自适应演出调度迁移

## 调整目标

- 将同一次权威操作产生的表决提交与结算事件合并为一个场景。
- 快速连续问答时自动缩短动画，避免演出落后于真实提问权。
- 指认、最终提名和轮末揭晓优先于旧的问答与表决进度动画。
- 不通过场景字段公开地点、间谍身份、赞成或反对内容以及反对者身份。

## 事件优先级

- 4级紧急：主动指认、最终提名、地点揭晓、轮末结果。
- 3级关键：指认驳回、超时提名开始、提名权交接。
- 2级普通：提问权就绪、定向提问、回答完成。
- 1级低价值：匿名表决已经提交。

## 调度参数

- 正常场景：1500毫秒。
- 待播场景达到2个：700毫秒追赶播放。
- 待播场景达到5个：压缩旧场景并以360毫秒播放。
- 4级紧急场景到达时，清除尚未播放的1～2级旧场景；正在播放的场景不会被强制中断。

## 新体验外壳中的演出定位

- 玩家不再按左右两列定位，而是映射为3～8人各自预设的非对称特工节点。
- 每个节点通过静态通信线连接中央上行链路；当前提问者、回答者和提名者的线路会增强显示。
- 权威提问、指认和提名轨迹继续使用稳定的 `data-player-id` 解析真实DOM位置，因此不依赖节点序号或固定像素。
- 普通问答使用青色信号，指认、提名和地点揭晓切换为红色警报；移动端隐藏装饰性静态线路，但保留行动者、目标与中央播报。
- 页面重构不改变事件字段、场景优先级、隐私边界或积压追赶逻辑。

## 验收标准

- [x] 每个产生演出事件的权威动作拥有独立 `sceneId`。
- [x] 同一动作内的多条事件共享场景，客户端只占用一次播放时长。
- [x] 非法动作和没有演出事件的操作不会消耗场景序号。
- [x] 事件优先级和场景序号随SQLite状态持久化。
- [x] 旧快照缺少场景字段时能够恢复并继续分配序号。
- [x] 自适应调度仅由game21显式启用，不改变其他游戏。
- [x] 公开事件继续隐藏地点、间谍身份和秘密票值。
- [x] 演出可在分布式节点和移动端列表之间重新定位，不依赖旧左右席位。
- [ ] 完成真实联机验收：快速连续问答、主动指认、同意票积压、反对驳回、超时提名和轮末揭晓。
