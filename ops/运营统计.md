# 桌游运营统计部署

报表是独立 HTML 文件，包含近 7 天、近 30 天的逐日访问和开局趋势、各入口访问量及 21 款已上架桌游的表现。同一文件可离线打开。以下示例假定项目在 `/srv/tablegame`，Node.js 24 已在执行命令的账号 PATH 中。

## 1. 收集生产站页面访问

将仓库的 `ops/analytics-nginx.conf` 引入 Nginx 的 `http {}` 一次。可在 `http {}` 写入以下指令。

```nginx
include /srv/tablegame/ops/analytics-nginx.conf;
```

在主站和大厅列出的各游戏 HTTPS `server {}` 内加上这一行。保留原有运维访问日志；原来由上级继承的 `access_log` 需要在本级一同写出。若某个页面的 `location` 自行设置了访问日志，也要在该级同时启用统计日志。主站原有的首页内部重写、静态目录与游戏反代均可沿用。

```nginx
access_log /var/log/nginx/tablegame-visits.log tablegame_visit if=$tablegame_log;
```

运行 `sudo nginx -t`，成功后运行 `sudo systemctl reload nginx`。从普通浏览器依次访问主站首页、大厅和快艇骰子，再查看 `tail /var/log/nginx/tablegame-visits.log`。三行应依次显示主站的 `root`、`index` 和快艇骰子子域名的 `root`。采用原始请求路径识别入口，首页的内部重写仍记作首页。随笔、工具页、拼图及拼豆工坊分别归类。

独立日志只记录请求随机 ID、时间、域名和入口分类。成功或缓存校验成功的 GET 计一次，忽略资源、房间 API、SSE、常见爬虫和健康检查。完全命中浏览器缓存的浏览不会到达 Nginx。此指标为页面访问次数，不能还原独立访客数。

## 2. 启用对局统计

先在快艇骰子（`game3`）和 CABO（`game13`）的生产游戏服务环境里设置 `TABLEGAME_ANALYTICS=1`，保留各服务原有的端口及数据库路径，在适当的维护时段用现有服务管理器重启。使用现有 SQLite 房间库时会自动新增统计表，无需清库或迁移旧房间。发布前的存量房间只从下一次实际观察到开局时计局，历史建桌数和已开始对局不作推算。本地试玩和自动检查默认关闭采集，应使用各自独立的房间库。

实测时，快艇骰子应在登记最后一格时新增一场正常完局。CABO 可在首轮结束时先生成一次报表，此时应仍为「1 开局、1 进行中」，继续下一轮也应保持这一计数。再试同房重新开局、房主中止、玩家重连。验证通过后，在其余已上架游戏的生产服务设置同一变量，重启后报表应显示「对局数据 21/21 款」。未上架的德州扑克及开发中的 Just One 不纳入桌游榜。

## 3. 生成并查看报表

让执行报表的账号可读取专用 Nginx 日志以及各游戏正在使用的 SQLite 库（含 WAL/SHM）；不要向公共网站目录复制房间库。各游戏使用自定义 `GAME3_DB_PATH`、`GAME13_DB_PATH` 等路径时，报表进程也必须设置**相同的绝对路径**。未指定时读取各游戏目录原本的 `.data/<目录名>.sqlite`。

用报表账号执行以下命令。生成目录应在所有静态站及游戏目录之外，仅对管理员开放。

```sh
cd /srv/tablegame
export TABLEGAME_REPORT_DIR=/var/lib/tablegame-report
sh scripts/update-analytics.sh
```

将 `/var/lib/tablegame-report/report.html` 通过现有 SSH/SFTP 下载到自己的电脑，直接用浏览器打开。可以用同一账号的 crontab 每小时刷新一份。cron 中需要提供 Node 的 PATH、与生产一致的数据库路径。以下示例适用于 Node 已在默认 PATH 的服务器。

```cron
17 * * * * TABLEGAME_REPORT_DIR=/var/lib/tablegame-report /bin/sh /srv/tablegame/scripts/update-analytics.sh
```

脚本导入当前日志及上一份 `.1` 或 `.1.gz`，再原子替换报表。将专用日志纳入服务器现有的 Nginx 日志轮转配置。停机跨越多份轮转日志时可手动补录留存文件，再运行更新脚本；同一请求 ID 重复导入只记一次。

```sh
node scripts/import-visits.cjs /var/lib/tablegame-report/visits.sqlite /var/log/nginx/tablegame-visits.log*
```

遇到损坏日志行，导入会报告行数并返回非零退出状态。已成功导入的行可以安全重读。无专用日志的历史日期不具备同口径访问数据。报表若显示游戏「尚未接入」，先核对游戏服务的开关、是否已重启及报表读取的数据库路径。

## 4. 阅读数据

- 日期采用北京时间，近 7 天和近 30 天都含今天。当天数字截至最近更新。每日开局只汇总已接入的游戏。
- 开桌率按建桌日筛选房间，观察其中有多少桌真正开始过。再玩率也使用这批房间，分母为其中正常完过局的桌，分子为首次正常完局后又开过局的桌。跨日继续游玩会更新原建桌日期的表现。
- 结局按开局日归属；正常完局、中断、过期和进行中之和等于开局数。参与人次按每局开局时的实际玩家席位累计，旁观与重连不增加人次。
- CABO、牛头王、拉密及间谍危机以整场比赛结算为终点。局内人每次独立揭晓算一局。我话你猜按自身规则由房主结分，正常结分算完局；移出玩家造成的结束算中断。其他项目房主主动中止、因掉线结束和房间回收分别计入中断或过期。
- 报表只含汇总。统计表保存随机桌号、局号、席位数、时间与结局，房间回收后解除与可复用房间码的关联。昵称、私牌和恢复令牌仍只属于游戏原有房间系统。
