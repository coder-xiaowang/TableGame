# game16《政变》演出队列防积压

## 目标

- 保留服务端 `reactionId + reactionKind` 对并发响应窗口的权威校验。
- 为服务器接受的声明、行动、阻挡和质疑生成持久化 `sceneId` 与优先级。
- 快速连续响应时让质疑和阻挡优先于尚未播放的普通行动声明。
- 动画仅说明已经发生的公开行动，不展示玩家真实的未公开身份。

## 优先级与播放速度

- 身份声明和普通行动为 3 级场景。
- 阻挡和质疑为 4 级紧急场景；到达时清除尚未播放的普通旧声明，但不打断当前场景。
- 正常播放 1600ms；2 个待播场景时以 700ms 追赶；4 个待播场景时以 360ms 快速追赶。

## 验收重点

1. 玩家连续质疑或阻挡时，中央播报应尽快对应当前服务端响应窗口。
2. 使用旧 `reactionId` 提交的操作继续被服务端拒绝，且不产生演出事件或消耗场景编号。
3. 宣称角色只是一项公开声明，不得借动画证明玩家确实持有该角色。
4. 首次加入或重连不回放历史演出；SQLite 重启后场景编号继续递增。
