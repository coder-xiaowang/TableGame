# game17《股海纵横》演出层迁移说明

## 目标

把服务器已经裁决的供给、竞价、交割、行情变化、卖出与分红转换为可感知的市场事件，让玩家能够看清“谁对哪个市场对象做了什么”。演出层不参与规则计算，也不提前展示尚未公开的牌、内幕或持仓。

## 服务器事件

| 阶段 | 主要事件 | 表现方向 |
| --- | --- | --- |
| 开市 | `round-start`、`supply-turn` | 中央市场与当前配置者 |
| 配置供给 | `supply-place` | 玩家到明牌堆，暗牌堆同时高亮 |
| 竞价 | `bidding-start`、`bid` | 玩家报价流向股票堆，被超价玩家同步提示 |
| 交割 | `stockpiles-resolved` | 股票堆与获胜投资人同时聚焦 |
| 市场行动 | `market-action`、`price-move` | 行动者指向公司行情牌；拆股/破产提高优先级 |
| 卖出 | `sale` | 投资人到涉及公司的成交回报 |
| 行情公布 | `information-reveal` | 内幕来源指向公司，随后显示价格移动 |
| 分红 | `dividend-turn`、`dividend` | 公司向公开持股的投资人支付现金 |
| 收盘 | `round-review`、`game-result` | 本轮或整局结算居中展示 |
| 超时 | `timeout-default` | 说明服务器已执行合法默认选择 |

## 隐私边界

- `supply-place` 可以公开明牌内容和明暗牌落入哪个股票堆，但不得包含暗牌ID或内容。
- 玩家供给手牌、私人内幕、具体公司持仓在规则允许公开前不得写入演出事件。
- 股票堆交割只携带原本已经公开的牌名；暗牌获得后仍只反映为公开持股数量。
- 行情组合进入 `revealedInformation` 后才能生成 `information-reveal`。
- 旁观者接收与普通公共视图相同的事件，不拥有额外推断字段。

## 实时性策略

- 一次操作及其紧随的阶段推进共用 `sceneId`，客户端只重点演出同场景最高优先级结果。
- 两个待播场景开始追赶，五个场景进入强压缩；拆股、破产、交割和收盘保留高优先级。
- 行情集中揭晓按公司分场景，使每次价格变化仍可辨认；积压时缩短至约320毫秒。
- 初次加入、刷新和断线重连只建立游标，不重播历史交易。
- 演出层不阻挡按钮、选择器或移动端吸附操作区。

## 验收重点

1. 暗放牌在所有无权视图和演出事件中均不出现内容或ID。
2. 连续竞价时新报价及时覆盖旧表现，不产生长时间延迟。
3. 最后一枚竞价标记与股票堆交割属于同一场景，以交割为主演出。
4. 行动牌导致的普通涨跌、拆股和破产均准确指向对应公司。
5. 集中行情结算不会阻塞后续分红操作。
6. SQLite 恢复后事件序号继续递增，刷新页面不重播旧行情。
