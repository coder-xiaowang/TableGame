# game13《CABO》演出层迁移说明

## 演出目标

CABO 的演出围绕“牌从哪里来、移动到哪里、哪一个牌位受到影响”展开。规则和牌值仍由服务器权威裁决；客户端只播放服务器已经确认的事件，不能以本地动画推断或提前改变状态。

## 事件与物件方向

| 事件 | 方向/表现 | 隐私 |
| --- | --- | --- |
| `round-start` | 中央牌桌进入初始记忆 | 不含牌值 |
| `memory-sealed` | 玩家提交初始选择 | 只公开“已提交” |
| `initial-memory` | 高亮自己的两个牌位 | 仅该玩家收到 |
| `turn-start` | 当前玩家席进入行动状态 | 公开 |
| `draw-deck` | 牌库飞向当前玩家 | 不含抽到的牌值 |
| `draw-discard` | 公开弃牌飞向当前玩家 | 可携带原本公开的牌值 |
| `exchange` / `match-success` | 玩家牌区完成替换 | 不公开新插入的隐藏牌值 |
| `match-failed` | 所选牌位公开并醒目震荡 | 牌位及牌面已经进入公共状态 |
| `failed-placement` | 新增牌向左端或右端归位 | 不含隐藏牌值；公开是否罚牌 |
| `power-use` | 能力牌从玩家移向弃牌堆 | 只公开能力类型 |
| `private-reveal` | 精确高亮查看牌位 | 仅发动能力的玩家收到，不把值写入事件 |
| `target-notice` | 精确高亮被操作牌位 | 仅目标玩家收到，不含牌值 |
| `swap` | 发起者到目标玩家的交换轨迹 | 公共事件不含具体牌位和牌值 |
| `cabo-call` | 高优先级 CABO 宣告 | 公开 |
| `round-result` | 牌面揭晓与本轮结算 | 仅在服务端完成结算后公开 |

## 队列策略

- 同一动作产生的主要事件和下一位玩家的 `turn-start` 使用同一个 `sceneId`，只重点播放其中高优先级事件。
- 队列达到2个场景时缩短播放；达到5个场景时强压缩。
- CABO、匹配成败、私人牌位提示和轮末揭晓可以抢占尚未播放的低价值提示。
- 首次加入、刷新和断线重连只建立事件游标，不补播旧动画。
- 减少动态效果偏好的设备会缩短运动，但仍保留文字播报。

## 隐私验收

1. 旁观者和无关玩家看不到牌库抽牌值、初始记忆牌位和 PEEK/SPY 精确目标。
2. SPY 发动者能看到目标牌值；目标玩家只知道自己的哪个牌位被查看。
3. SWAP 目标知道被交换牌位，但不会凭事件获得牌值。
4. 公共事件与私人事件共用全局递增序号，SQLite 恢复后不会重复或乱序。
5. 旧房间快照缺少演出字段时能够自动补齐并继续运行。
