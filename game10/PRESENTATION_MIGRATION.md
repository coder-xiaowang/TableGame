# game10《Can't Stop》桌面演出层迁移

## 迁移目标

保留原有“服务器生成随机种子与骰面、浏览器按种子复播物理骰子”的实现，用共享权威演出层补齐玩家方向、路线推进、扎营、爆掉、占峰和胜负强调。演出只消费服务端已经确认的事实，不改变规则、不代替状态渲染。

## 权威事件

| 事件 | 表现内容 | 优先级 |
| --- | --- | --- |
| `game-start` | 登山开始和首位玩家 | 4 |
| `turn-start` | 回合交接 | 1 |
| `roll-start` | 玩家开始投掷 | 1 |
| `dice-settled` | 四颗权威骰面公开 | 2 |
| `route-chosen` | 骰子区指向本次推进路线，突出临时进度 | 3 |
| `turn-stopped` | 扎营并把临时进度固化 | 3 |
| `turn-busted` | 爆掉并失去本回合临时进度 | 4 |
| `summit-claimed` | 占领一座或多座峰顶 | 4 |
| `game-result` | 占领三座峰顶并获胜 | 5 |

所有字段都是公开信息，玩家和旁观者收到完全相同的演出事件。事件由服务器生成递增序号，客户端不从游戏记录反推演出。

## 物理动画与共享演出的分工

- 现有三维骰子继续负责真正的滚动轨迹与落定画面，共享层不会再画一套飞行骰子。
- 路线中的登山者与营地仍由权威视图直接渲染；共享层只添加方向轨迹、路线聚焦和中央短播报。
- 扎营与同次产生的占峰使用同一 `sceneId`，播放器优先表现“占领峰顶”，避免连续重复播报同一结算。
- 普通播放 1250ms；积压达到 2 个场景后缩短到 580ms，达到 5 个后缩短到 300ms并压缩低优先级事件。爆掉、占峰和胜负属于不可轻易丢弃的高优先级结果。
- 首次进入和断线重连只建立事件游标，不重放历史；旧 SQLite 房间缺少演出字段时会自动补齐。

## 实机验收

- [ ] 掷骰仍只有原来的四颗三维骰子，没有第二套骰子或重复声音。
- [ ] 选择组合后，轨迹从骰子操作区指向对应路线；双数推进及两条路线都得到强调。
- [ ] 临时登山者和已经扎营的营地视觉上可区分，演出不改变任何格数。
- [ ] 扎营后进度固化；若同时到达峰顶，以占峰提示为主，不重复播两次同义结算。
- [ ] 无合法组合时醒目提示爆掉，并强调失去临时进度的路线。
- [ ] 占领三条路线后及时显示胜负，不被之前的掷骰或回合提示拖延。
- [ ] 快速操作、超时自动操作时不会长期播放过期动画。
- [ ] 玩家与旁观者看到相同的公开骰面、推进和结算演出。
- [ ] 刷新、断线重连和服务重启不会重播历史演出或重复推进。
- [ ] 手机端行动区仍可点击，演出层不拦截触控；减少动态效果设置下可正常使用。
